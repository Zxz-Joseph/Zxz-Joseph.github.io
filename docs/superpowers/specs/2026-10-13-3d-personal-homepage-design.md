## 人像与方案选择

用户最新要求：人像必须风格化，不直接展示原照片。采用半写实的手办角色方向，以照片作为外形参考，提炼脸型、黑色短发、五官、白色衣领和深蓝外套。正常显示真实三维 GLB 模型；备用图也使用该角色的渲染图。原站作者的人像与个人资产不复用。

模型参考已在本地准备：`/Users/zxz/Desktop/self_projects/site-planning/portrait-reference.jpg`，是原照片的头部及上半身裁剪，原图保留。单张照片不能确定侧面和背面细节，因此角色采用艺术化设计，检查正面、侧面和背面后使用。

实施方式调整为本地程序建模，创建原创几何和材质，导出 GLB 后在浏览器检查正面与侧面，并生成同风格的备用渲染图。形象是基于照片特征提炼的艺术角色，不宣称扫描复原或精确重建本人三维面部。原照片保存在仓库外，不作为网页资产。

此前用户已授权向 Meshy 上传照片，上传已完成；免费产物的 CC BY 4.0 许可未获确认，未提交生成。本地原创模型不使用该服务产物，也不需要接受该公开许可。

## 实现边界

- 基于参考站的 MIT 许可代码重建 React/TypeScript/Vite 静态站，保留必要许可及字体许可；不复用原作者模型、履历、作品图、商标和个人文案。
- 个人内容放入独立配置；经历组件使用三段数据；3D 场景根据新模型包围盒确定尺度与镜头，不依赖原模型中的 CameraAction 或定位节点。
- 桌面端固定 3D 场景随滚动切换视角，文字保持可读；手机端减少镜头幅度和特效，并给人像与正文留出空间。
- 模型加载失败或设备不支持 WebGL 时，显示该风格化角色的静态渲染图与完整文字，联系入口仍可用；尊重系统减少动态效果设置。
- 不添加文章系统、后台、登录、分析追踪或未经用户要求的项目内容。
- 使用 GitHub Pages 构建部署，资源路径支持站点根目录；不修改独立的 hello-agents-8-week 项目。

## 验证与发布

先本地检查 TypeScript、lint 和生产构建，再在真实浏览器验证桌面及手机宽度：滚动镜头、人像纹理、中文排版、邮箱和 GitHub 链接、加载失败备用显示、减少动态效果。检查生成产物不包含原作者文案、旧博客入口和非公开简历信息。

生成模型需单独检查相似度、几何、纹理和体积，必要时压缩后使用。最后部署到原 GitHub Pages 主页，并访问线上页面验证资源加载和公开内容。
